# 구현과 한계

버추얼 종이컵은 센서 입력으로 수면을 계산하고 Canvas 2D 또는 Three.js의 WebGL 3D로 표시하는 브라우저 앱입니다. 사용 방법은 [README](../README.md), 실행·검증은 [개발 안내](DEVELOPMENT.md)에 있습니다.

## 코드 구조

| 파일 | 역할 |
| --- | --- |
| `src/core/types.ts` | 벡터·기울기·센서 샘플 타입 |
| `src/core/attitude.ts` | 기준 자세의 직교 기저, 기울기 변환, 저역통과 필터 |
| `src/core/cup.ts` | 높이장 스프링·댐퍼, 파동, 넘침과 물 손실 |
| `src/sensor.ts` | DeviceMotion 지원·권한 확인과 이벤트 구독 |
| `src/scene-coordinates.ts` | 센서 기준 평면의 앞뒤 축을 화면·3D 장면 좌표로 변환 |
| `src/render.ts` | 컵의 정면 단면, 수평계, 기울기 표시 |
| `src/core/water-surface.ts` | 원판 수면 보간, 경계 유출을 각도별 구간으로 변환 |
| `src/core/spill-flight.ts` | 센서 유효 중력과 수두·상승 속도로 외벽 이탈 및 자유 유출 궤적 계산 |
| `src/render-3d.ts` | 종이 재질의 컵, 수면, 외벽 유출과 3D 장면 |
| `src/core/liquid-stream.ts` | 유출 이력, 물줄기 단면, 분열 입자와 충돌 계산 |
| `src/render-pour.ts` | 동적 물줄기 메시, 굴절 방울, 잔물보라와 바닥 효과 |
| `src/runoff.ts` | 컵 외벽을 따르는 물막 경로와 아래쪽으로 전달되는 유량 연출 |
| `src/audio.ts` | Web Audio 알림음과 지원 기기의 진동 |
| `src/calibration-storage.ts` | 기준 중력 벡터 저장·검증·기저 복원 |
| `src/preferences.ts` | 설정값 검증·저장·기본값 복원과 선명도 상한 |
| `src/main.ts` | 화면 상태·입력·프레임 진행·세션 결과 |

`src/core/`는 브라우저 API를 사용하지 않으며 시간을 인자로 받습니다. 물리와 자세 계산은 Node.js 테스트로 확인합니다. 기존 테스트는 `core.test.ts`, `spill-loss.test.ts`, `overturn.test.ts`에 있으며 저장소 방어 규칙은 `repo-policy.test.mjs`에서 검증합니다.

## 화면 상태와 입력

기본 흐름은 `idle → leveling → ready → running → stopped`입니다. 기준 설정은 1.5초가 지나면 끝나며, 실행 중에는 종료 버튼 또는 물 소진으로 결과 화면에 들어갑니다. 결과 화면에서 같은 기준으로 다시 시작하거나, 기준을 다시 잡거나, 전체 상태를 초기화할 수 있습니다.

센서가 지원되고 권한이 허용되면 중력 포함 가속도를 사용합니다. 센서 미지원 또는 권한 거부 시에는 마우스·방향키 입력을 사용합니다. 센서 구독은 기준 설정 전에 시작하며 페이지가 열린 동안 유지됩니다. 기준 중력 벡터는 브라우저 로컬 저장소에 보관하고 재방문 시 검증하여 기저를 복원합니다. 저장된 기준으로 시작할 때도 센서 권한을 확인합니다. 결과는 메모리에만 두고 저장하거나 서버로 전송하지 않습니다.

개발 서버에는 화면 확인과 고정 기울기를 위한 쿼리가 있습니다. 프로덕션 빌드에서는 쿼리를 입력으로 읽지 않고 자동 시작·샘플 결과 화면 경로도 제외합니다.

## 설정과 적용 시점

설정은 네이티브 `dialog.showModal()`로 엽니다. 열면 제목에 포커스를 두고 배경 조작을 막으며, 닫기·Esc·배경 클릭으로 닫은 뒤 열었던 버튼에 포커스를 돌립니다. PC에서는 오른쪽 패널, 폭 600px 이하에서는 아래쪽 패널로 표시합니다. 내용만 스크롤하고 닫기와 완료 버튼은 유지합니다. 기준을 수집하는 동안에는 설정 버튼을 비활성화합니다.

| 옵션 | 적용 시점 | 저장 |
| --- | --- | --- |
| 그래픽 모드·선명도·게이지 | 즉시 | 예 |
| 시점 고정 | 즉시, 드래그 회전에만 적용 | 예 |
| 방향 버튼·시점 초기화 | 즉시, 방위각과 고도 변경 | 아니요 |
| 시작 물 높이·물 높이 유지 | 다음 측정 시작 | 예 |
| 현재 컵에도 이 높이 적용 | 현재 컵에 `setFill()` 적용, 기록 보존 | 시작 높이만 저장 |
| 소리·진동 | 이후 알림부터 적용 | 예 |

측정 중 설정을 열면 입력 필터·컵 적분·물 애니메이션 시계를 멈춥니다. 닫을 때 정지 시간을 시작 시각에 더하므로 경과 시간에서 제외됩니다. 렌더링은 계속해 선명도와 시점 변경을 미리 볼 수 있습니다. 진동 API가 없는 환경은 해당 스위치를 비활성화하며, API가 있다는 것만으로 실제 진동을 보장하지는 않습니다.

`papercup-preferences`에는 옵션만 저장합니다. 기존 `papercup-render-mode`가 있으면 이전 2D 선택을 이어받습니다. 허용한 자료형·범위의 값만 복원하고 손상된 JSON이나 접근 실패는 기본값으로 처리합니다. 저장 실패는 패널에 표시합니다. 화면·알림 복원은 물 설정을 보존하며, 측정 결과는 계속 메모리에만 둡니다. `preferences.test.ts`에서 저장 복원, 이전 선택 이관, 손상·접근 실패, 기본값 복원의 범위를 검증합니다.

## 자세 보정

기준 설정 중 수집한 가속도의 평균으로 위쪽 방향 `up`을 구합니다. 화면의 x축에서 `up` 성분을 제거해 `ex`를 만들고, 외적으로 `ey`를 구합니다. x축과 중력 방향이 나란하면 화면의 y축을 사용합니다. 이후 유효 중력을 이 기저에 투영해 수면 기울기를 계산합니다.

폰이 기울어진 상태로 장착되어도 기준 자세를 보정할 수 있습니다. 중력만으로 차체 전후 방향의 회전인 요를 결정할 수는 없습니다. 화면 축과 차량 방향의 관계를 자동으로 찾아내는 기능은 없습니다. 가속과 중력도 별도로 추정하지 않으므로 표시 각도는 합성된 유효 기울기입니다.

센서 기준 평면의 앞쪽 `+y`는 화면 위쪽에 대응합니다. 장면의 격자 `+y`는 3D의 `+z`로, 기본 카메라에 가까운 쪽이므로 `sensorTiltToScene()`에서 센서 기울기의 y 부호를 반전합니다. 좌우와 뒤집힘 판정은 유지합니다. 초기 3D 구현은 이 변환이 없어 앞뒤가 반대로 표시됐습니다. 방향키·포인터·개발용 `tx`, `ty` 입력은 기본 시점 기준이므로 이 부호 변환을 생략합니다.

3D에서는 평활한 입력을 `rotateTiltByYaw()`로 카메라의 방위각만큼 수평 회전한 뒤 물리 계산에 전달합니다. 컵 반대편에서 보더라도 화면 기준 좌우·앞뒤 입력 방향을 유지합니다. 위아래로 보는 카메라 고도는 이 계산에 넣지 않으며, 기울기의 크기와 뒤집힘 판정은 그대로 유지합니다. 수평계와 최대 기울기 기록은 시점 회전 전 입력을 사용합니다. 2D에서는 시점에 따른 변환을 하지 않습니다.

수평 성분을 수직 성분으로 나눌 때 분모는 기준 중력 크기의 0.15배 이상으로 제한합니다. 유효 중력과 컵 축으로 계산한 `cosTilt`가 0.12 미만이면 `overturned`로 처리합니다. 이는 약 83도부터의 모델상 처리 기준입니다. 뒤집힘 입력은 저역통과 필터를 우회하며 실행 중 각도 표시는 90도로 대체됩니다.

유출 궤적에는 비율로 바꾼 기울기와 함께 보정된 유효 중력 벡터를 전달합니다. 벡터도 앞뒤 부호 보정·평활·카메라 방위각 변환을 거치며, 수직 성분의 부호를 보존해 90도를 지나도 낙하 방향을 잃지 않습니다. 카메라 고도는 중력 벡터를 바꾸지 않습니다. 합성 입력은 기울기에서 같은 좌표의 중력을 구성합니다.

기존 문서의 “90도를 넘으면 수평 성분이 0이 된다”는 설명은 부정확했습니다. 완전히 뒤집힌 경우에는 수평 성분이 0에 가까워질 수 있으므로, 기울기 크기와 별도로 방향을 판정하는 것이 구현의 목적입니다.

## 컵과 물 손실

컵 원판 안의 24×24 격자에서 수면 높이 편차와 속도를 적분합니다. `DEFAULT_CUP`의 기본값은 채움 비율 0.72, 복원 계수 90, 파동 계수 45, 감쇠 7, 손실 계수 0.35입니다. 프레임 시간은 최대 50ms로 제한하고 4ms 이하의 서브스텝으로 나눕니다.

경사진 평형 높이로 돌아가는 복원력, 이웃 높이 차이에 따른 파동, 속도에 비례하는 감쇠를 계산합니다. 벽과 바닥에 맞춰 높이를 제한합니다.

넘침은 경계 칸의 높이와 경사 평형이 벽을 넘는 정도를 함께 봅니다. 제한된 높이만 사용하면 매 스텝 초과량이 작아져 손실이 멈추는 문제가 있으므로 두 값 중 큰 값을 사용합니다. 손실 속도는 넘침 정도의 1.2승에 비례합니다. 이전 문서의 토리첼리 법칙과 지수 대응 설명은 이 코드의 물리적 정확성을 증명하지 않으므로 모델 정의와 구분합니다.

물이 줄면 기준 수면도 내려가 같은 기울기에 덜 넘칩니다. 뒤집힘에서는 `spillRate × 14`의 초당 비율로 물을 줄입니다. 채움 비율이 0.12 이하이면 앱이 물 소진으로 세션을 끝냅니다. **물 높이 유지**를 켜면 같은 계산으로 넘침량만 누적합니다. 결과의 `1컵`은 컵의 최대 용량이며, 누적값은 이를 넘을 수 있습니다.

`setFill()`은 컵을 다시 만들지 않고 기준 수면을 옮겨 출렁임과 누적 넘침 횟수를 보존합니다. 넘침 상태 표시는 초기화해 새 수위에서 넘침을 다시 판정합니다. `reset()`은 물량·손실량·출렁임·횟수를 초기화합니다.

기존 기울기별 잔량 표는 정확한 실측값을 제시하지 않았습니다. 현재 테스트는 78도에서 55도보다 더 많이 줄어드는지, 88도에서 빠르게 소진되는지 등 정해진 입력의 조건을 확인합니다.

## 렌더링

2D 격자를 좌우 열별로 평균 내고 한 번 평활해 정면 단면을 그립니다. 물리 계산에는 전후 방향도 들어가지만 화면은 그 전체 분포를 표현하지 않습니다. 이전 문서에 있던 “전후 기울기가 수면 전체 높이를 밀어 올린다”는 별도 처리 경로는 현재 렌더러에 없습니다.

시험 3D 모드는 원판의 높이장을 보간해 원뿔 모양의 컵 내벽에 맞는 수면 메시를 만듭니다. 컵의 위치·자세는 고정하고, 센서 입력은 수면의 출렁임과 경계 유출에만 반영합니다. 초기 시험 구현에서는 유효 기울기를 컵 회전에도 적용했으나, 시점을 안정적으로 유지하도록 이 동작을 제거했습니다.

카메라는 `OrbitControls`로 한 손가락 또는 마우스 왼쪽 버튼 드래그에만 반응합니다. 컵을 중심으로 회전하며 바닥 아래로 내려가지 않도록 고도를 제한합니다. 자동 회전·관성·확대·이동은 끄고, 시점 초기화 버튼으로 처음 구도를 복원합니다. 화면 크기가 바뀌면 거리를 조절하되 선택한 방위각과 고도는 유지하며, 2D로 바꿨다가 돌아와도 같은 시점을 사용합니다. 3D 드래그는 물 기울기 입력에서 제외하고, 센서가 없는 환경에서는 방향키로 물을 조작합니다. 2D의 기존 마우스 입력은 유지합니다.

물리 적분 중 경계 칸의 넘침 강도, 제한 전 초과 수두, 상승 속도를 `edgeOverflow`, `edgeHead`, `edgeRiseSpeed`에 기록합니다. 이를 40개 각도 구간으로 모아 실제 넘침이 발생한 테두리에서 유출을 시작합니다. 수두와 유효 중력 크기로 초기 속도를 구하고, 외벽 바깥으로 작용하는 중력과 유출 관성이 커질수록 부착 비율을 줄입니다. 분리된 물은 정규화 시계의 1/90초 간격으로 위치와 속도를 기록하고 `p = p₀ + vt + ½gt²`로 이동합니다. 이후 센서 입력이 바뀌어도 이미 방출한 물의 위치·속도를 유지하며, 새 가속도만 적용합니다. 컵은 고정되므로 장면의 아래 방향과 물이 가속되는 방향은 기울기에 따라 달라집니다. 높이 약 2인 컵 모델을 10cm로 가정하여 1 장면 단위를 0.05m로 환산합니다. 유출 시계는 실제 시간의 `1 / sqrt(0.05)`배로 진행하므로, 실제 초 기준 속도는 약 4.47배, 가속도는 20배가 됩니다. 수평 상태의 약 10cm 자유 낙하는 약 0.14초에 해당합니다. 이는 자유 유출 표시의 크기 보정이며 컵 내부 수면과 누적 손실 계산의 시간은 바꾸지 않습니다.

외벽에 남는 약한 넘침은 둥근 테두리와 좁아지는 옆면을 따라 흐릅니다. 유량을 아래로 전달해 약 0.85초에 걸쳐 도착하고, 공급이 멎은 뒤에도 남은 물은 배수됩니다. 가는 물줄기의 불규칙 경로·합류·굵기 변화와 방울은 시각 연출로 보완합니다. 크게 기울였을 때는 외벽 경로의 공급을 줄이고 테두리에서 떨어져 나가는 물줄기로 전환합니다.

자유 유출은 원형 테두리에서 실제로 이어진 넘침 구간을 찾아 구간 하나당 하나의 덩어리로 표시합니다. 초기 구현의 고정 8방향 분할은 같은 넘침을 여러 가닥으로 나누는 문제가 있어 제거했습니다. 0도와 360도를 가로지르는 구간도 이어서 처리하며, 떨어져 있는 구간은 합치지 않습니다. 독립 구간은 유량 순으로 최대 4개까지 보관하고 이전 출발점과 가까운 구간에 연결해 유량 순위가 바뀌어도 궤적이 뒤바뀌지 않게 합니다. 입구에서는 컵 테두리의 곡률을 따라 이어지고, 짧은 거리에서 중앙으로 모인 뒤 불규칙한 목과 단면 변화를 거쳐 분열합니다. 누적 손실량의 증가분을 체적 유량으로 환산하고, `Q = A·v` 관계로 가속되는 물줄기의 단면을 좁힙니다. 높이 기반 손실 모델을 화면에 맞추기 위한 체적 환산값 4.58과 단면 계수 0.4, 반지름 상한 0.24를 사용하므로 정밀한 체적 해석은 아닙니다. 공급이 끊기거나 출발점이 크게 바뀌면 연결을 분리합니다.

물줄기 끝이 가늘어져 목이 끊어지면 해당 구간의 표면·위치·가중 평균 속도를 분리된 덩어리로 넘깁니다. 분리 순간에 작은 입자로 교체하지 않습니다. 같은 표면을 세로 18개 단면으로 보간한 뒤 실제 시간 약 45ms 동안 둥글게 수축시키며, 구의 크기는 원래 단면적과 길이로 구한 표시 체적에서 정합니다. 긴 꼬리는 짧은 구간으로 나누고 서로 다른 방출 이력은 합치지 않습니다. 덩어리는 둥글어진 뒤에도 같은 메시와 중력 적분을 사용하며 바닥에 닿으면 잔물보라를 만듭니다. 이는 [NASA의 작은 물방울과 표면장력 설명](https://gpm.nasa.gov/resources/students-and-educators/the-shape-of-a-raindrop)을 참고한 형태 근사입니다.

분리 덩어리는 최대 24개, 잔여 입자는 최대 900개, 물줄기는 연결 구간당 최대 72개 표본으로 제한하고 정점·인스턴스 버퍼를 재사용합니다. 별도로 방출하는 방울은 `InstancedMesh`, 미세 입자는 가장자리가 부드럽게 사라지는 `Points` 셰이더로 표시합니다. 바닥 충돌은 실제 낙하 지점에 작은 튀김, 퍼지는 고리, 젖은 자국을 남깁니다. 빠른 방향 변화에서 메시가 접히지 않도록 표시 중심선을 이웃 표본으로 보간하고, 그 곡선에 수직으로 단면을 배치합니다. 법선은 변형된 면에서 다시 계산합니다. 이 표시 보간은 물리 위치와 입자 속도를 바꾸지 않습니다.

[컵 사이에 물을 붓는 실사 영상](https://elements.envato.com/a-woman-interacting-with-an-object-isolated-on-the-U76TV78)의 약 3초와 16초 구간에서 이어진 유출과 굵기 변화를 관찰해 입구의 연결 형태를 비교했습니다. 후속 검토에서는 약 5초와 13초의 굵은 부분·가는 목·방울 전환을 참고했습니다. 영상은 참고용으로 열람했으며 프로젝트 에셋으로 사용하지 않습니다.

물줄기에는 굴절률 1.333과 `transmission`, 두께, 환경 반사를 사용합니다. [Three.js 재질 문서](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)의 투과 방식과 [지오메트리 스킬](https://github.com/CloudAI-X/threejs-skills/blob/main/skills/threejs-geometry/SKILL.md)의 동적 버퍼·인스턴싱 방식을 참고했습니다. 다중 렌더 패스가 필요한 [화면 공간 유체 렌더링](https://developer.download.nvidia.com/tools/docs/Fluid_Rendering_Alice.pdf) 대신, 모바일에서 다룰 수 있는 제한된 메시와 파티클을 사용합니다. 작은 화면에서는 물이 컵 밖으로 나가는 구간을 담도록 기본 카메라 거리를 늘립니다.

물의 감소와 누적 넘침량은 기존 `Cup` 계산이 소유하며, 입자 수로 물량을 다시 계산하지 않습니다. 유출 속도의 손실 계수·상한, 부착력의 전환 범위, 외벽 전달 시간은 정규화한 컵에 맞춘 근사값입니다. 분열 시점과 표시 체적은 시각 근사입니다. 분리 전후의 크기를 연결하되 수축 중 메시 체적이나 입자 부피의 합으로 엄밀하게 질량을 보존하지는 않습니다. 표면장력의 정밀 해석, 입자 사이의 충돌·합류, 원뿔 내부의 정확한 체적 보존, 회전 좌표계의 관성항은 구현하지 않았습니다. 뒤집힘에서도 수평 중력 방향이 남아 있으면 해당 방향의 테두리로 유출하며, 완전히 뒤집혀 수평 성분이 사라지면 물리 계산은 전체 테두리의 유출을 사용합니다. 3D 표시는 구간 폭에 상한이 있어, 이때의 고리 모양 유출까지 재현하지는 않습니다.

컵 몸체는 별도 무늬나 굴곡 텍스처 없이 매끈한 흰색 재질로 표시하며, 조명 환경은 코드로 생성합니다. 외부 모델·텍스처를 다운로드하지 않습니다. 3D 코드는 선택할 때 별도 청크로 로드합니다. 선명도별 화면 배율 상한은 가볍게 1, 균형 1.75, 선명하게 2이며 투과 렌더링의 해상도 비율은 각각 0.4, 0.6, 0.85입니다. 물리 격자와 물줄기 계산은 선명도에 따라 바꾸지 않습니다. 모드 전환은 같은 `Cup`과 세션 상태를 유지하고, 선택값만 브라우저의 로컬 저장소에 기록합니다. 초기화 실패·렌더링 실패·WebGL 연결 손실 시 기존 2D 화면으로 돌아갑니다.

## 남은 동작 한계

- 센서 API 존재와 권한 허용을 실제 샘플 도착과 구분하지 않습니다. 기준 설정의 샘플이 5개 미만이면 표준 자세로 대체하며, 이때도 준비 완료로 표시될 수 있습니다.
- 안정도는 표시하지만 기준 설정 완료를 막는 조건으로 사용하지 않습니다. 센서 중단·오래된 샘플·비정상 수치에 대한 처리도 보강이 필요합니다.
- 설정 패널을 연 동안을 제외하면 모든 상태에서 물리 스텝을 진행합니다. 결과 표시 이후의 잔여 출렁임과 반복 시작 시 표시 초기화는 별도 동작 검증이 필요합니다.
- 탭 비활성화·화면 잠금·복귀 시 경과 시간과 물리 진행 시간이 달라질 수 있습니다.
- 실기기 센서·권한·소리·진동, 화면 회전, 차량 장착 상태와 주행 상황은 이번 저장소 감사에서 검증하지 않았습니다.

이 항목은 현재 구현의 제한입니다. 문서·정책 감사 과정에서 센서와 물리 동작을 함께 재설계하지 않았으며, 기능 변경 시 별도의 재현과 검증이 필요합니다.
