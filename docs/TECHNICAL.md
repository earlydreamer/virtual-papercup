# 구현과 한계

가상 종이컵은 센서 입력으로 수면을 계산하고 Canvas 2D 또는 Three.js의 WebGL 3D로 표시하는 브라우저 앱입니다. 사용 방법은 [README](../README.md), 실행·검증은 [개발 안내](DEVELOPMENT.md)에 있습니다.

## 코드 구조

| 파일 | 역할 |
| --- | --- |
| `src/core/types.ts` | 벡터·기울기·센서 샘플 타입 |
| `src/core/attitude.ts` | 기준 자세의 직교 기저, 기울기 변환, 저역통과 필터 |
| `src/core/cup.ts` | 높이장 스프링·댐퍼, 파동, 넘침과 물 손실 |
| `src/sensor.ts` | DeviceMotion 지원·권한 확인과 이벤트 구독 |
| `src/scene-coordinates.ts` | 센서 기준 평면의 앞뒤 축을 화면·3D 장면 좌표로 변환 |
| `src/render.ts` | 컵의 정면 단면, 수평계, 기울기 표시 |
| `src/core/water-surface.ts` | 원판 수면 보간, 경계 유출을 각도별 구간으로 변환 |
| `src/render-3d.ts` | 종이 재질의 컵, 수면, 물막·물줄기·물방울 표시 |
| `src/audio.ts` | Web Audio 알림음과 지원 기기의 진동 |
| `src/main.ts` | 화면 상태·입력·프레임 진행·세션 결과 |

`src/core/`는 브라우저 API를 사용하지 않으며 시간을 인자로 받습니다. 물리와 자세 계산은 Node.js 테스트로 확인합니다. 기존 테스트는 `core.test.ts`, `spill-loss.test.ts`, `overturn.test.ts`에 있으며 저장소 방어 규칙은 `repo-policy.test.mjs`에서 검증합니다.

## 화면 상태와 입력

기본 흐름은 `idle → leveling → ready → running → stopped`입니다. 기준 설정은 1.5초가 지나면 끝나며, 실행 중에는 종료 버튼 또는 물 소진으로 결과 화면에 들어갑니다. 결과 화면에서 같은 기준으로 다시 시작하거나, 기준을 다시 잡거나, 전체 상태를 초기화할 수 있습니다.

센서가 지원되고 권한이 허용되면 중력 포함 가속도를 사용합니다. 센서 미지원 또는 권한 거부 시에는 마우스·방향키 입력을 사용합니다. 센서 구독은 기준 설정 전에 시작하며 페이지가 열린 동안 유지됩니다. 결과는 메모리에만 두고 저장하거나 서버로 전송하지 않습니다.

개발 서버에는 화면 확인과 고정 기울기를 위한 쿼리가 있습니다. 프로덕션 빌드에서는 쿼리를 입력으로 읽지 않고 자동 시작·샘플 결과 화면 경로도 제외합니다.

## 자세 보정

기준 설정 중 수집한 가속도의 평균으로 위쪽 방향 `up`을 구합니다. 화면의 x축에서 `up` 성분을 제거해 `ex`를 만들고, 외적으로 `ey`를 구합니다. x축과 중력 방향이 나란하면 화면의 y축을 사용합니다. 이후 유효 중력을 이 기저에 투영해 수면 기울기를 계산합니다.

폰이 기울어진 상태로 장착되어도 기준 자세를 보정할 수 있습니다. 중력만으로 차체 전후 방향의 회전인 요를 결정할 수는 없습니다. 화면 축과 차량 방향의 관계를 자동으로 찾아내는 기능은 없습니다. 가속과 중력도 별도로 추정하지 않으므로 표시 각도는 합성된 유효 기울기입니다.

센서 기준 평면의 앞쪽 `+y`는 화면 위쪽에 대응합니다. 장면의 격자 `+y`는 3D의 `+z`로, 기본 카메라에 가까운 쪽이므로 `sensorTiltToScene()`에서 센서 기울기의 y 부호를 반전합니다. 좌우와 뒤집힘 판정은 유지합니다. 초기 3D 구현은 이 변환이 없어 앞뒤가 반대로 표시됐습니다. 방향키·포인터·개발용 `tx`, `ty` 입력은 기본 시점 기준이므로 이 부호 변환을 생략합니다.

3D에서는 평활한 입력을 `rotateTiltByYaw()`로 카메라의 방위각만큼 수평 회전한 뒤 물리 계산에 전달합니다. 컵 반대편에서 보더라도 화면 기준 좌우·앞뒤 입력 방향을 유지합니다. 위아래로 보는 카메라 고도는 이 계산에 넣지 않으며, 기울기의 크기와 뒤집힘 판정은 그대로 유지합니다. 수평계와 최대 기울기 기록은 시점 회전 전 입력을 사용합니다. 2D에서는 시점에 따른 변환을 하지 않습니다.

수평 성분을 수직 성분으로 나눌 때 분모는 기준 중력 크기의 0.15배 이상으로 제한합니다. 유효 중력과 컵 축으로 계산한 `cosTilt`가 0.12 미만이면 `overturned`로 처리합니다. 이는 약 83도부터의 모델상 처리 기준입니다. 뒤집힘 입력은 저역통과 필터를 우회하며 실행 중 각도 표시는 90도로 대체됩니다.

기존 문서의 “90도를 넘으면 수평 성분이 0이 된다”는 설명은 부정확했습니다. 완전히 뒤집힌 경우에는 수평 성분이 0에 가까워질 수 있으므로, 기울기 크기와 별도로 방향을 판정하는 것이 구현의 목적입니다.

## 컵과 물 손실

컵 원판 안의 24×24 격자에서 수면 높이 편차와 속도를 적분합니다. `DEFAULT_CUP`의 기본값은 채움 비율 0.72, 복원 계수 90, 파동 계수 45, 감쇠 7, 손실 계수 0.35입니다. 프레임 시간은 최대 50ms로 제한하고 4ms 이하의 서브스텝으로 나눕니다.

경사진 평형 높이로 돌아가는 복원력, 이웃 높이 차이에 따른 파동, 속도에 비례하는 감쇠를 계산합니다. 벽과 바닥에 맞춰 높이를 제한합니다.

넘침은 경계 칸의 높이와 경사 평형이 벽을 넘는 정도를 함께 봅니다. 제한된 높이만 사용하면 매 스텝 초과량이 작아져 손실이 멈추는 문제가 있으므로 두 값 중 큰 값을 사용합니다. 손실 속도는 넘침 정도의 1.2승에 비례합니다. 이전 문서의 토리첼리 법칙과 지수 대응 설명은 이 코드의 물리적 정확성을 증명하지 않으므로 모델 정의와 구분합니다.

물이 줄면 기준 수면도 내려가 같은 기울기에 덜 넘칩니다. 뒤집힘에서는 `spillRate × 14`의 초당 비율로 물을 줄입니다. 채움 비율이 0.12 이하이면 앱이 물 소진으로 세션을 끝냅니다. **물 높이 유지**를 켜면 같은 계산으로 넘침량만 누적합니다. 결과의 `1컵`은 컵의 최대 용량이며, 누적값은 이를 넘을 수 있습니다.

`setFill()`은 컵을 다시 만들지 않고 기준 수면을 옮겨 출렁임과 누적 넘침 횟수를 보존합니다. 넘침 상태 표시는 초기화해 새 수위에서 넘침을 다시 판정합니다. `reset()`은 물량·손실량·출렁임·횟수를 초기화합니다.

기존 기울기별 잔량 표는 정확한 실측값을 제시하지 않았습니다. 현재 테스트는 78도에서 55도보다 더 많이 줄어드는지, 88도에서 빠르게 소진되는지 등 정해진 입력의 조건을 확인합니다.

## 렌더링

2D 격자를 좌우 열별로 평균 내고 한 번 평활해 정면 단면을 그립니다. 물리 계산에는 전후 방향도 들어가지만 화면은 그 전체 분포를 표현하지 않습니다. 이전 문서에 있던 “전후 기울기가 수면 전체 높이를 밀어 올린다”는 별도 처리 경로는 현재 렌더러에 없습니다.

시험 3D 모드는 원판의 높이장을 보간해 원뿔 모양의 컵 내벽에 맞는 수면 메시를 만듭니다. 컵의 위치·자세는 고정하고, 센서 입력은 수면의 출렁임과 경계 유출에만 반영합니다. 초기 시험 구현에서는 유효 기울기를 컵 회전에도 적용했으나, 시점을 안정적으로 유지하도록 이 동작을 제거했습니다.

카메라는 `OrbitControls`로 한 손가락 또는 마우스 왼쪽 버튼 드래그에만 반응합니다. 컵을 중심으로 회전하며 바닥 아래로 내려가지 않도록 고도를 제한합니다. 자동 회전·관성·확대·이동은 끄고, 시점 초기화 버튼으로 처음 구도를 복원합니다. 화면 크기가 바뀌면 거리를 조절하되 선택한 방위각과 고도는 유지하며, 2D로 바꿨다가 돌아와도 같은 시점을 사용합니다. 3D 드래그는 물 기울기 입력에서 제외하고, 센서가 없는 환경에서는 방향키로 물을 조작합니다. 2D의 기존 마우스 입력은 유지합니다.

물리 적분 중 각 경계 칸에서 발생한 초과량을 `edgeOverflow`에 기록하고, 40개 각도 구간으로 모아 해당 테두리에서 물막과 물줄기를 시작합니다. 물방울은 고정된 장면의 아래 방향으로 떨어지고 바닥에서 한 번 튑니다. 물의 감소와 누적 넘침량은 기존 `Cup` 계산이 소유하며, 입자 수로 물량을 다시 계산하지 않습니다. 물막·방울·바닥의 젖은 영역과 미세 잔물결은 시각 연출입니다. 정밀 유체 해석, 물막의 충돌·합류, 원뿔 내부의 정확한 체적 보존은 구현하지 않았습니다. 뒤집힘은 컵의 자세를 유지하면서 기존 판정에 맞춰 전체 테두리 유출과 물 감소로 표현합니다.

종이 섬유와 조명 환경은 코드로 생성합니다. 외부 모델·텍스처를 다운로드하지 않습니다. 3D 코드는 선택할 때 별도 청크로 로드하며 화면 배율을 1.75로 제한합니다. 모드 전환은 같은 `Cup`과 세션 상태를 유지하고, 선택값만 브라우저의 로컬 저장소에 기록합니다. 초기화 실패·렌더링 실패·WebGL 연결 손실 시 기존 2D 화면으로 돌아갑니다.

## 남은 동작 한계

- 센서 API 존재와 권한 허용을 실제 샘플 도착과 구분하지 않습니다. 기준 설정의 샘플이 5개 미만이면 표준 자세로 대체하며, 이때도 준비 완료로 표시될 수 있습니다.
- 안정도는 표시하지만 기준 설정 완료를 막는 조건으로 사용하지 않습니다. 센서 중단·오래된 샘플·비정상 수치에 대한 처리도 보강이 필요합니다.
- 물 높이 슬라이더는 실행 중에도 조작할 수 있습니다. 정지 상태에서 설정하도록 하는 정책을 UI가 강제하지는 않습니다.
- 애니메이션은 모든 상태에서 물리 스텝을 진행합니다. 결과 표시 이후의 잔여 출렁임과 반복 시작 시 표시 초기화는 별도 동작 검증이 필요합니다.
- 탭 비활성화·화면 잠금·복귀 시 경과 시간과 물리 진행 시간이 달라질 수 있습니다.
- 실기기 센서·권한·소리·진동, 화면 회전, 차량 장착 상태와 주행 상황은 이번 저장소 감사에서 검증하지 않았습니다.

이 항목은 현재 구현의 제한입니다. 문서·정책 감사 과정에서 센서와 물리 동작을 함께 재설계하지 않았으며, 기능 변경 시 별도의 재현과 검증이 필요합니다.
